# Contributing to cartiva

First off, thank you for taking the time to contribute!

Contributions are what make the open-source community such an amazing place to learn, inspire, and create. Any contributions you make are greatly appreciated.



## Code of Conduct
By participating in this project, you agree to abide by its terms. 



## How Can I Contribute?
### Reporting Bugs

Before creating bug reports, please check the existing issues as a similar problem might have already been reported. When you create a bug report, please include as much detail as possible:

*   **Use a clear and descriptive title** for the issue.
*   **Describe the exact steps to reproduce** the problem.
*   **Provide specific examples** (include code snippets, error logs, or screenshots if applicable).
*   **Describe what you expected to happen** and what actually happened.
*   **Include details about your environment** (OS, browser, app version, Node.js version, etc.).

### Suggesting Enhancements

This section guides you through submitting an enhancement suggestion for cartiva. 
Following these guidelines helps maintainers and the community understand your suggestion and find related issues.

*   **Use a clear and descriptive title** for the issue.
*   **Provide a detailed description of the enhancement**, explaining why it would be useful to most users.
*   **List any alternative solutions or features** you've considered.

### Pull Requests

If you are ready to fix a bug or implement a feature, follow these steps:

1.  **Fork the repo** and clone it to your local machine.
2.  **Create a new branch** from `main` (or `dev`):
    ```bash
    git checkout -b feature/your-feature-name
    # or
    git checkout -b fix/your-bug-name
    ```
3.  **Make your changes**, ensuring you follow the project's coding style guidelines.
4.  **Run tests** (if applicable) to make sure nothing is broken:
    ```bash
    npm test
    ```
5.  **Commit your changes** using clear and descriptive commit messages (following conventional commits if applicable):
    ```bash
    git commit -m "feat: add amazing new feature"
    ```
6.  **Push to your fork** and submit a Pull Request to the main repository:
    ```bash
    git push origin feature/your-feature-name
    ```

## Style Guides

### Git Commit Messages
*   Use the present tense ("Add feature" not "Added feature").
*   Use the imperative mood ("Move cursor to..." not "Moves cursor to...").
*   Reference issues and pull requests liberally after the first commit message line.
